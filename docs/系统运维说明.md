# 管理员健康检查

管理员登录后，在左侧进入「系统运维」（`/#/admin`）。普通用户不显示入口，直接访问页面会回到通知单；后台 `/api/admin/health` 也会校验管理员角色，无登录返回401，普通用户返回403。

## 检查内容

- API响应：当前请求已通过登录与管理员权限检查。
- Ubuntu服务：固定检查 hydro-oa-api、hydro-oa-worker、nginx、mysql，显示运行状态、开机自启与服务自动重启次数。不需要为API增加sudo权限。
- 数据库：连接与查询、通知单数量、已采集月份、最近数据更新时间。
- 同步：最近10轮的开始/结束时间、处理月份、失败月份及安全错误类型；最近一轮失败会标记异常，即使worker处于active也不显示同步成功。
- 源系统网络：从X5_CONFIG_PATH读取配置，仅检测域名解析与TCP端口，最多等待约4秒，不登录、不查询源系统。端口可连接不等于凭据有效或采集成功。
- 详情爬取模板：检查主单/零件/工装私密请求模板是否可读；不自动登录源系统。
- 通知单详情爬取探测：管理员可填写某单 `HEC_TechnologyOrder`（或留空用库内最新一条），显式调用 `/api/admin/health/detail-probe` 实测登录与详情查询；默认超时约20秒，结果不写库、不进入小时同步。

## 刷新和判断

页面默认每分钟自动刷新，仅页面可见时请求；可以取消自动刷新或手动刷新。后台将一次检查结果缓存30秒，返回实际检查时间与剩余缓存时间，避免多人频繁发起网络探测。时间统一展示为北京时间。

无同步记录、最近成功记录超过两小时没有新轮次、运行超过两小时的同步都会提醒关注；这只是运维提示，长时间采集不被自动判定为失败。运行记录来自sync_runs，数据更新时间来自成功写入的sync_months。只有最近一次实际成功的采集才能反映数据更新，不使用服务active作为替代。

本页默认只读，不提供重启、配置修改、小时同步触发或原始日志下载；「测试详情爬取」为管理员显式探测例外。未安装systemd的开发环境会标记服务状态未确认。API或数据库整体故障导致无法校验会话时，页面可能也无法读取，应使用服务器终端检查；刷新失败时界面会明确标记下方数据为历史快照。

## 部署

无新增Python或npm依赖，无数据库表结构变化。更新源码、执行npm run build后，重启hydro-oa-api即可加载接口；无需重启worker。配置仍使用shared/service.env，不在页面展示私密路径、密码、Cookie、源请求或原始异常文字。
